## Загрузка

1. Загрузить свежий архив Majestic-Discord-Bridge.zip через Files и распаковать в /home/container. В корне должны лежать index.js и package.json, рядом — папки cloud, tools, majestic-forum-api и integrations. Не оставлять всё внутри дополнительной папки с названием архива.
2. Локально выполнить `node cloud/scripts/setup.js`: команда создаёт .env из .env.example и генерирует разные приватные ключи API_READ_TOKEN, API_WRITE_TOKEN, EXECUTOR_TOKEN, DISCORD_BRIDGE_TOKEN, OAUTH_CLIENT_SECRET и OWNER_PASSWORD. Значения в консоль не выводятся; существующий .env не перезаписывается. Готовый .env загрузить отдельно в /home/container рядом с index.js. В общий архив конфигурация с ключами не включается. Значения PUBLIC_URL, CLOUD_URL, PORT и два guild ID уже подставлены в пример. При подключении ChatGPT сверить точный адрес OAuth-переадресации с его диалогом подключения. Ключи в чат присылать не нужно.
3. Стандартную команду Startup, которая заканчивается node /home/container/index.js, можно оставить. Новый index.js загружает .env и запускает сервер. Штатная команда Wispbyte устанавливает зависимости из package.json перед запуском.
4. При редактируемой команде можно использовать npm start: она дополнительно задаёт предел кучи Node 256 МБ. Альтернатива — задать NODE_OPTIONS=--max-old-space-size=256 в переменных окружения панели (не полагаться на чтение этого параметра из .env внутри уже запущенного index.js).
5. Запустить сервер. /health должен вернуть JSON с ok:true и service:majestic-workspace-cloud. Статус Active в Subdomains подтверждает наличие маршрута, но не запуск приложения. Страница Wispbyte Web server isn't running означает, что приложение ещё не слушает выделенный порт.
6. В плагине Vencord адрес назначения — https://apimjd.wispbyte.app, ключ — DISCORD_BRIDGE_TOKEN этого сервера. Оба Discord-сервера уже выбраны. Настройка и сборка плагина описаны в discord-vencord.md.
