# Обновление SQLite, 24.11.2026

Подготовлено для уже работающего Majestic Discord Bridge. На момент сборки это обновление проверено локально, но ещё не установлено на Wispbyte.

## Установка на действующий сервер

1. Остановить приложение в панели Wispbyte.
2. В `/home/container/cloud/src` сохранить прежние `store.js`, `discord-bridge.js` и `server.js`, переименовав каждый с окончанием `.pre-storagefix-20261124.bak`. Если копия с таким именем уже есть, использовать другое свободное имя.
3. Загрузить `Majestic-Discord-Storage-Fix.zip` в корень `/home/container` и распаковать там. В архиве только эти три обновлённых модуля и инструкция `INSTALL.txt`.
4. Запустить приложение с прежней командой запуска. Настройки Vencord менять и пересобирать плагин не требуется.
5. При первом запуске приложение создаст и проверит резервную копию базы в настроенном DATA_DIR, подпапке `backups`. Только после успешной проверки оно удалит точные дубли текущих редакций. Реальные сообщения, прежние редакции и подтверждённый курсор сохраняются. При ошибке backup процесс остановится до очистки; код причины будет в журнале запуска.
6. Проверить `discord_export_status` для обоих выбранных серверов. Новое поле `storage` подтвердит обновление. Следить за ростом `messageCount` и изменением `lastDataAt`. `bridgeOnline:true` отдельно не доказывает продвижение.

В архиве нет `.env` и базы. Для действующей установки не запускать первоначальную настройку и не заменять эти данные. При развёртывании из GitHub `dadidkil/mjapi` использовать коммит, содержащий оба исправления INVALID_TEXT и SQLite. Обновление репозитория само по себе не подтверждает установку кода на Wispbyte.

## Что исправлено

- Ошибка заполнения SQLite больше не скрывается повторным ROLLBACK. При достижении квоты страница отклоняется целиком с EXPORT_QUOTA, без сдвига курсора и ложного завершения выгрузки.
- Текущая редакция хранится один раз. API истории возвращает её вместе с сохранёнными предыдущими редакциями и сохраняет пагинацию.
- Освобождённые страницы используются следующими пакетами. Размер самого файла может остаться прежним: свободное место внутри базы видно как `storage.reusableBytes`.
- Включено прежнее исправление INVALID_TEXT для исходных сообщений с управляющими символами.

Проверка: 76 тестов успешно, 0 ошибок, 1 тест официального SDK MCP пропущен из-за недоступной зависимости; синтаксис 40 файлов и 25 путей OpenAPI. Реальное заполнение тестовой SQLite, миграция с проверенным backup и продолжение импорта в пределах прежнего числа страниц проверены отдельно.

В живой базе пока подтверждены 43 528 сообщений первого сервера; второй ждёт в очереди. Размер живой базы ещё не измерен. Полная выгрузка и её возобновление после этого обновления пока не подтверждены. Если места окажется недостаточно и после очистки дублей, потребуется отдельное решение по объёму хранения; старые сообщения автоматически удаляться не будут.
